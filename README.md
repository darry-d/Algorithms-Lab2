##  Опис проєкту
Цей репозиторій містить вихідний код для другої лабораторної роботи з дисципліни "Алгоритми та структури даних". Робота розділена на дві незалежні частини, які досліджують різні аспекти оптимізації та збереження даних.

### Частина 1: Time Complexity vs Space Complexity (Варіант 4)
Дослідження компромісу між часом виконання та використанням оперативної пам'яті на прикладі задачі: **Перенесення нулів в кінець масиву**. 
Реалізовано три підходи:
1. **Наївний (Рівень 1):** Час $O(N^2)$, Пам'ять $O(1)$. Зсув елементів в межах одного масиву.
2. **Жадібний (Рівень 2):** Час $O(N)$, Пам'ять $O(N)$. Створення додаткового масиву-копії.
3. **Оптимальний (Рівень 3):** Час $O(N)$, Пам'ять $O(1)$. Використання методу "двох покажчиків" (Two Pointers) для перестановки елементів In-Place.

*Тестування проводилося на масиві з 100 000 елементів із заміром часу (System.nanoTime) та пам'яті (Runtime.totalMemory).*

### Частина 2: Базові концепції хешування (Варіант 5)
Реалізація власної простої хеш-функції без використання вбудованого методу `hashCode()`.
* **Алгоритм:** Хешування сумою ASCII-кодів з урахуванням позиції символу у рядку.
* **Математична модель:** Сума добутків (код символу * індекс) ділиться із залишком на просте число M (997).
* **Тестування:** Алгоритм перевірено на згенерованому масиві з 1000 унікальних слів для підрахунку кількості колізій (згідно з принципом Діріхле).
