# Емпіричний аналіз складності алгоритмів та базові концепції хешування (Лабораторна робота №2)

**Виконала:** студентка групи WEB-25, Крутогуз Д.О.

## Опис проєкту
Цей репозиторій містить вихідний код для другої лабораторної роботи з дисципліни "Алгоритми та структури даних". Робота розділена на дві незалежні частини, які досліджують різні аспекти оптимізації алгоритмів та збереження даних.

## Частина 1: Time Complexity vs Space Complexity (Варіант 4)
Дослідження компромісу між часом виконання та використанням оперативної пам'яті на прикладі задачі: **Перенесення нулів в кінець масиву**. Реалізовано три підходи:
* **Наївний (Рівень 1):** Час O(N^2), Пам'ять O(1). Зсув елементів здійснюється в межах одного масиву.
* **Жадібний (Рівень 2):** Час O(N), Пам'ять O(N). Створення додаткового масиву-копії для збереження ненульових елементів.
* **Оптимальний (Рівень 3):** Час O(N), Пам'ять O(1). Використання методу "двох покажчиків" (Two Pointers) для перестановки елементів *In-Place* без залучення додаткової пам'яті.

**Методологія тестування:**
Тестування проводилося на масивах розміром 100 000 елементів.
* Для точного вимірювання часової складності та уникнення похибок "холодного старту" JVM використано спеціалізовану бібліотеку **JUnit Benchmarks** із налаштуванням раундів прогріву (*warmupRounds*).
* Для вимірювання просторової складності (витрат оперативної пам'яті) використано низькорівневий інтерфейс **ThreadMXBean** (`com.sun.management.ThreadMXBean`). Це дозволило з високою точністю зафіксувати кількість байтів, виділених безпосередньо потоком виконання алгоритму. Заміри проводилися циклічно у три ітерації, що дозволило наочно продемонструвати стабілізацію показників пам'яті після прогріву віртуальної машини Java та мінімізувати вплив Cold Start.

## Частина 2: Базові концепції хешування (Варіант 5)
Реалізація власної простої хеш-функції без використання вбудованого методу `hashCode()`.
* **Алгоритм:** Хешування сумою ASCII-кодів з урахуванням позиції символу у рядку, що дозволяє мінімізувати кількість колізій для слів-анаграм.
* **Математична модель:** H(S) = (∑ (S[i] * (i + 1))) mod M, де M — просте число (997).
* **Тестування:** Алгоритм перевірено на згенерованому масиві з 1000 унікальних випадкових рядків. Отримані результати підрахунку колізій емпірично підтверджують дію принципу Діріхле при обмеженому просторі хеш-адрес.
